# Supported contract (v1)

Python 3.10–3.13, Windows/macOS/Linux; standard library runtime. Local CLI, no network or database. CSV and JSON UTF-8 (CSV BOM allowed). Maximum 16 source files, 50,000 total records, 20 MiB per file, 32 review windows, 4096 characters per cell. No CSV formulas in generated spreadsheets: formula-leading cells are prefixed with an apostrophe; the tool removes its own single prefix when reading its generated decision worksheet.

`gage-window analyze project.json --out DIRECTORY` creates a new directory only; never overwrites. Exit 0 = report produced with no unresolved rows; 2 = report produced, unresolved evidence needs attention; 1 = invalid input or operation failed, no report published. These exit codes do not indicate conformance or investigation closure. `review REPORT --decisions CSV --out DIRECTORY` accepts a complete, unaltered case identity set; exit 2 while any case has status open, 0 when all have a recorded reviewed or escalated status. Neither status asserts product conformance. `verify REPORT` checks all expected files against hashes, validates embedded analysis identity, regenerates classification from bundled sources; no authenticity or external completeness claim. `example DIRECTORY` creates a runnable constructed example.

Project JSON has exactly: `schema_version: 1`, `gages: [canonical IDs]`, `aliases: {exact spelling: canonical ID}`, `windows: [{id, gage_id, start, end, reason}]`, `sources: [{name, path, kind, columns}]`. Relative paths resolve against project directory. Files are user-authorized local files, never URLs. Source names and IDs are nonempty printable strings. Canonical IDs compare exactly; no fuzzy/automatic case folding. Alias chains and canonical remapping forbidden. All window gages must be known. Windows require offset-aware second-or-microsecond timestamps, inclusive start/end; reason required, start <= end. Humans choose windows; the tool never calculates last-known-good, safe-release time, drift or tolerance.

Each source has kind `direct` or `custody` and columns mapping `gage_id`, `work_id`, `start`, optionally `end` and `reference` to distinct CSV headers. No auto-detection. CSV headers unique/nonempty, extra columns preserved. Source rows are never silently dropped or deduplicated; blank/malformed records become unresolved. Direct blank end = point use; custody blank end = open-ended possible custody. Exact second/microsecond timestamps must have Z or ±HH:MM offset. Date-only YYYY-MM-DD means a possible instant anywhere in that UTC day. No local calendar dates, naive timestamps, ambiguous formats or inferred DST. For intervals, earliest possible start through latest possible end is conservative; end before start is unresolved.

Per row, preserve source name, logical CSV record number (header=1), original cell strings, stable source hash/row ID, canonical gage, normalized bounds, matched window IDs, classification, reasons. Known nonsuspect gage -> other_gage. Unknown/blank gage -> unresolved even when its date appears outside. Invalid/missing date -> unresolved unless known nonsuspect gage (issues still retained). Known suspect gage with no window overlap -> outside_window; open intervals remain unbounded. Direct evidence whose entire conservative span is contained in any one matching window -> recorded_overlap. Other direct partial overlaps, coarse boundary overlaps, and all custody overlaps -> possible_overlap. Missing work_id on otherwise in-scope evidence -> unresolved. All matched windows remain listed, even when another one fully contains the record. Inclusive boundary equality overlaps. Duplicate records remain separate and are flagged.

Cases group all in-scope/unresolved rows by exact work_id; missing work ID gets its own case per record. No case means only that supplied rows produced no candidates; unlogged work cannot be inferred. Worksheet immutable fields: analysis_id, case_id, work_id, record_ids, window_ids. Editable fields: status (open/reviewed/escalated), owner, rationale, evidence. Non-open cases require all three text fields. Every case must be present exactly once; no extras or identity edits. Changing sources/windows/mappings creates a new analysis and invalidates prior decisions. Review outputs preserve analysis and original report, final decision CSV and readable report. Hashes are integrity checks only; a malicious editor can rewrite a bundle.

Output report is static escaped HTML for reading/printing, JSON for machine use, records CSV and cases CSV for review; no JavaScript, remote resources or executable content. An HTML report is a document, not an interactive product UI. Inputs and outputs may contain sensitive shop data; users control local access. No gauge calibration, engineering assessment, compliance certification, automated recall, customer outreach or product release decision. Evidence kind and mappings are user assertions. Custody must never be presented as proof of measurement.
