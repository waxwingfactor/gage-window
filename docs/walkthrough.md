# From disconnected exports to recorded follow-up

1. Preserve original exports. Normalize local date/time data into documented UTC dates or offset-aware timestamps. Decide which IDs identify individual gauges and which work IDs distinguish the jobs/lots being investigated. Record those decisions outside the tool when needed.
2. Use `gage-window example demo` for a complete project skeleton. Replace the known `gages` list and explicit `aliases`. Aliases are exact assertions; the tool never discovers equivalences. A typo or unmapped spelling becomes unresolved. A reused asset tag needs separate, explicitly disambiguated identities before import.
3. Choose `windows` with your qualified investigator. Every window needs a canonical gage, ID, exact offset-aware start/end, and reason. Windows are inclusive. The tool neither recommends a last-known-good instant nor assumes a later passing calibration clears earlier product.
4. Add each CSV source with its own column mapping. `kind: direct` asserts the record names a gauge actually used; `custody` only asserts possession/check-out. If a file mixes these meanings, split it explicitly first. Extra source columns are preserved as original evidence. The `reference` mapping is optional context, not an automatically fetched link.
5. Run `analyze` into a new directory. A malformed schema/file fails with exit 1. A valid report with unresolved rows returns 2. Read the classification counts and every unresolved reason before using the candidate list. Source row numbers count CSV records, including quoted multiline records and blank rows.
6. Read `report.html` or `analysis.json`. Inspect `records.csv` for excluded rows as well as candidate cases. `outside_window` only describes supplied windows; `other_gage` only describes supplied identity assertions. No candidates does not imply no exposure. Original cells plus extra surplus cells are retained in `analysis.json`; originals remain in the bundled CSVs.
7. Copy `cases.csv` elsewhere. Edit only status, owner, rationale and evidence. Keep open cases open until follow-up is recorded. Reviewed/escalated are bookkeeping labels; use rationale/evidence to link your actual quality process. Do not remove cases, rewrite IDs, reorder headers or import a worksheet from a changed analysis. All rows must be returned once; row order may change.
8. Run `review` with the original report directory, completed decisions and a new output directory. On error, correct the worksheet; no output is published. Exit 2 means open cases remain. The resulting `decisions.csv` and HTML preserve your human follow-up with the original analysis. `cases.csv` remains the initial blank worksheet so the original candidate set is visible.
9. Run `verify` after moving or copying the entire directory. It reproduces accounting from the included input snapshots and checks the generated outputs. Use exactly the producing version of the tool. Keep bundle originals securely if authenticity matters; hashes alone do not stop a deliberate editor.

## Fixing evidence gaps

An unresolved row is a request for human investigation. Correct the source/configuration from actual evidence, then run a **new analysis** and a new worksheet. The previous worksheet must not be pasted into the new analysis: changed hashes and analysis identity intentionally invalidate it. You may read prior rationale and record a new decision yourself after checking the changed evidence. The tool cannot turn unknown identities into measured-use facts.

CSV output prefixes formula-leading strings (including leading spaces before =, +, -, @) and existing apostrophe-leading strings with an apostrophe. Identity columns must stay exactly as exported. Editable worksheet fields accept that same escaping convention; the importer removes a single recognized escape prefix. JSON stores the original cell strings. Avoid spreadsheet auto-conversion of IDs or timestamps; the importer detects identity changes and rejects them rather than guessing.

## Failure and resource boundaries

There are no external integrations or network calls. Expanded row evidence is limited to 8 MiB before rendering, including repeated headers and record identities; large exports may need splitting into smaller explicit projects. Source CSVs total at most 20 MiB, with 50,000 records total, at most 16 sources, 128 columns per source and 4096 characters per input cell. At most 32 windows and 10,000 known gauges/aliases are supported. Schema errors, unsupported timestamps or encodings, invalid headers, oversized data, altered identities and unexpected report files fail clearly. Relevant bad dates and row-width mismatches are retained as unresolved evidence instead of being silently filtered out.

Decision worksheets allow aggregate identity cells up to 4 MiB, so large cases can list their source rows. Human-editable values remain limited to 4096 characters after decoding. Reports and decision files are limited to 256 MiB per file; reports total at most 512 MiB. Inputs must be regular files, not symlinks. Use a local filesystem and one writer per output directory; interruption or storage failure requires verifying or regenerating the output. No process can make guarantees about hostile concurrent changes to local files.
